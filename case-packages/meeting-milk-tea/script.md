# 培训中低声点一杯奶茶

**一句话**：培训进行中不方便出声，用户压着嗓子让助手点一杯瑞幸茉莉花奶茶送到公司。
**到哪儿结束**：订单已创建、待支付，金额和预计送达报给用户，付款请他自己点卡片。
**角色**：用户全程耳语；助手 24～25 岁自然女声，跟着耳语把音量压下来，不外放、不放 Loading。

| 时间 | 谁 | 说什么 / 做什么 | 为什么 |
| --- | --- | --- | --- |
| 0.0–3.1 | 用户 | （耳语）帮我点一杯瑞幸的茉莉花奶茶。 | 培训中压着嗓子，语速偏慢 |
| 3.6–4.4 | 后台 | 任务=饮品下单，品牌=瑞幸，商品沿用原话 | 不因为归类成「订咖啡」改掉商品 |
| 4.8–6.8 | 工具 | 同时开跑：当前位置、常用地址、饮品偏好、瑞幸下单能力 | 互不依赖的准备工作并行 |
| 4.8–7.6 | 助手 | （轻声、慢半档）嗯……我看一下瑞幸这边。 | 垫句：等待要有人接住，但不外放 |
| 7.2–8.0 | 后台 | 位置对上「公司」；偏好没记录，不编；选中已授权的瑞幸能力 | 发现 ≠ 授权，拿到状态才敢用 |
| 8.4–10.0 | 工具 | delivery.quote → 12 元，约 30 分钟 | 报价 |
| 10.4–11.6 | 工具 | 确认卡片：茉莉花奶茶 ×1 / 公司 / 12 元 / 约 30 分钟 / 付款按钮 | 卡片和语音并行，语音不等卡片 |
| 10.4–14.8 | 助手 | 好的，一杯瑞幸茉莉花奶茶，送到公司，对吧？ | 下单前把商品和地点对一遍 |
| 15.3–16.2 | 用户 | （耳语）是的。 | 口头确认 |
| 16.8–18.5 | 助手 | （轻声）好，这就下单。 | 垫句：只表示收到，不宣布成功 |
| 16.8–17.6 | 后台 | 口头确认覆盖的是订单内容，不是支付 | 付款按钮仍要用户自己点 |
| 18.0–20.4 | 工具 | create_order → 待支付；卡片同时按语音自动确认 | 建单与卡片并行 |
| 20.8–21.6 | 后台 | 已创建、待支付；按返回值播报 | 不说「已付」「已接单」 |
| 22.0–23.2 | 工具 | 卡片转成待支付，付款按钮亮起 | 台词要用户点卡片，卡片得先看得见 |
| 23.6–29.7 | 助手 | 下好了，一共十二块，大概三十分钟送到。付款点一下卡片就行。 | 照返回值说，把付款交还给人 |

**打断 / 附和**：这条 Case 一次都没有——培训里没人抢话。考点在下单边界和口头确认的覆盖范围。

**预计时长**：约 29.7 秒（设计值，配音后按录音重排）。

脚本源文件是同目录的 `script.dsl`，改那份再跑
`node scripts/script-to-package.mjs case-packages/meeting-milk-tea` 重新切轨。
