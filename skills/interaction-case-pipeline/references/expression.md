# Assistant 表达控制

- 表达控制描述 Assistant 每条回复的表达方式，与对应助手片段逐条关联，起止时间完全对齐。回复间的空白不覆盖；不把整段模式状态画成贯穿 Case 的表达块。
- 语音按实际表达标垫句、持续平调鼻音“嗯”、慢说或明确要求的语气；普通确认、常规语速和打断停播不自动增加标签。未测量的声学表现标为目标，生成后按实际音频核对。
- 悄悄话模式每条助手回复标“悄悄话模式 · 仅文字回复”，说明不播报语音。助手不生成音频、波形或静音占位 WAV，不播放 Loading。进入或退出模式另记对应用户操作或世界事件。
- 文本回复保留稳定 message_id 与显示区间，放在助手轨道及 dynamic_context.text_messages；不进入语音 Utterances。表达标注在 custom_annotation 中记录 annotation_type=output_mode、role=assistant、mode=text_only、message_id、start_at_ms、end_at_ms。不支持文本的源包格式须先适配，或使用平台支持的 snapshot 包。
- 用户移动或调整助手片段时，通过稳定引用同步更新其表达区间。语音末端按实际音频，禁止尾部拖拽拉长；文字显示窗口可调整。表达控制不独立漂移。
- 同步维护轨道、Case JSON、查看 JSON 面板及导出包，修改后持久化。已有整段悄悄话标注须替换为逐条标注，避免重复。
- 每个 Case 保留表达控制轨道；无标注时默认折叠，不为撑满轨道添加无意义片段。

核对示例：助手在 6,000–8,000 ms 和 10,400–12,000 ms 显示两条文字回复，表达控制及 JSON 应各有相同区间的两条标注，8,000–10,400 ms 留空。第一条移动后，只同步其关联标注。
