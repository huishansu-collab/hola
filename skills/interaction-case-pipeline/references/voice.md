# 助手声音：描述、执行 Prompt 与验收

## 已确认的默认声音

助手是一位 24～25 岁的女性。她正在和熟悉的朋友说话，刚理解对方的需求，或刚看到一条相关信息，顺口接着聊。说话的对象就在身边，正常距离、正常聊天音量。声音自然、亲近、松弛，带一点明快感；情绪来自当前内容，整段不持续保持笑意。

采用自然成年女性的中音区。音色清晰、温暖，保留正常声带质感；音高随语义轻微变化。无需制造幼态、高亢、撒娇、刻意甜美、低沉磁性或明显气声。不要在每句起头加一口可闻吸气。

语速中等偏快，整体连贯、利落。信息充分时自然说完一句，短小连接词轻轻带过。按意思组织词组，例如“卡片发你了”可顺着说完；“Gmail”嵌入中文句子时自然衔接，不突然切换音色或逐字母停顿。复杂信息可以短暂停一下，不能为追求快而吞掉关键词。

重音放在当前有用的信息上：询问哪种邮箱时强调选择，确认时间时强调新时间，接收补充时轻松应答。少量重音足够，不把每个字读得同样清楚、同样重。连接词、代词、语气词可以弱读，但台词必须完整。

句末轻松收住。陈述句不固定大幅降调，问句不统一夸张上扬；避免拖长每个句尾或以朗诵式停顿分隔短语。呼吸与换气服务于句子，保留正常人声细节；不追加叹气、笑声、语气词、口水音或背景声音。

助手音轨为干净人声，无背景音乐、环境声和等待提示音。用户音色与环境按当前 Case 单独设定，不能套用助手默认女声。

## 直接用于生成的默认音色段

以下段落可放入 text_prompt 的助手角色说明。前面的分析用于选择和诊断，不必再次重复到请求中。

> 助手是一位 24～25 岁女性，普通话自然，像在和熟悉的朋友聊天，顺口接着对方的话说下去。声音清晰、亲近、松弛，采用自然成年女性的中音区和正常聊天音量，带一点轻快感。语速中等偏快，连贯、利落，按意思连读；小词轻轻带过，有用的信息稍微强调，不把每个字都念得一样重。需要换气时短暂停顿，句尾自然收住。保留正常人声细节，不刻意加气声、装甜、压低嗓音或在句首先吸气。不要客服、新闻播音或朗诵腔，不逐字念、不频繁断句、不刻意抑扬顿挫。只说指定台词。助手为干净人声，无音乐、环境声或提示音。

具体 Case 可用一句自然的关系背景替换开头，例如“刚查到结果，转头告诉朋友”。短信场景才使用“刚看到短信”；不要把短信情境套入查询、订咖啡等所有对白。

## 片段级表达

在明确需要的台词前附一条简短说明，不要改变整段基础声音。

| 场景 | 片段要求 |
|---|---|
| 正常回答 | 像刚想到这句话就自然说出来，连贯，不专门摆出播报姿态。 |
| 简短接收 | “好”“行”轻松、简短，有接住对方的话的感觉，不拉长或郑重宣布。 |
| 需要确认 | 平常地问朋友，保留一点询问语气，重点在待确认的信息上。 |
| 中英混说 | 英文词自然嵌入中文节奏，维持同一个人、同样音量和距离。 |
| 成功反馈 | 明确、利落，强调最终有效结果，不刻意兴奋，也不重复解释过程。 |
| 战术性慢说 | 只在该句略放缓并保留自然停顿，为工具争取时间；目标约常规语速的 0.85 倍，随后恢复基础语速。 |

少用“温柔播报”“舒缓”“字正腔圆”“每字清晰”“情绪饱满”等会把声音推向朗读的描述。不要同时要求快、极慢、很多停顿和一口气说完。

## 战术性“嗯”

仅在 Case 需要时安排。它是一段独立的发声和垫句标注，后面的句子沿用相同音色。

可用指令：

> 这一段只发一个闭口、连续的鼻音“嗯——”，像在思考时自然延续的声音。直接从有声鼻音开始，音高基本平稳、音量稳定，持续到指定的目标时长后自然结束。前面不先吸气或叹气，中间不停顿、不重新起音，不变成“呃”“啊”，尾部不明显下滑。保持当前助手的音色。

目标时长按该段任务节奏填写，并记为生成目标。工具很快返回时不强行拖长。正常句尾的“嗯”或表示肯定的“嗯”使用对应语义，不能套用持续鼻音。

若生成成了“呼吸声 + 短嗯”、下滑疑问音、分段哼声或时长不足，调整这条局部指令并重生成相关完整母带；不得用拉伸、循环拼接或变速伪装成符合要求的生成。

## 音色一致性

同一角色的多句台词默认来自同一次完整录音。用户的“就 Gmail”“是的”“对对”等短句也来自该用户母带，避免独立生成后的换人感。不同角色需要不同环境声时，可按角色分别生成整段母带，再按时间线叠放；一条混合录音不能保证环境声只跟随用户。

有用户已认可的音色时，先保存该版本的 Prompt、服务参数和母带引用。服务支持稳定 voice ID 或参考音频时，再按真实能力使用；仅重复文字描述不能保证跨请求完全相同。不得将随机 seed 当作跨版本一致音色的保证。

## 试听验收

生成后至少听：第一句、最长一句、短确认句、专有名词、被打断附近，以及单独的“嗯”。同一角色的相邻片段连续试听。

- 听起来像对身边的人说话；无客服、播音或刻意表演感。
- 句子连贯，小词有弱读、重点有轻重；没有逐字等时输出。
- 正常句保持利落，战术慢说只作用于指定片段。
- 相邻句、长句与短句为同一角色音色；英文词处不换人。
- 无漏词、加词、尾字丢失、剪断音节；自然度不能代替台词准确性。
- “嗯”从有声鼻音直接起，持续、平调，实测时长满足当前设计。
- 助手无环境声；用户场景声低于对白，角色间无意外串入。

ASR 检查覆盖度，波形检查切点和时长，试听检查自然度。没有实际试听能力时，报告尚未完成听感验收，提供片段供用户确认。

## 定向修正

一次修正一个主要问题：朗诵感优先减少逐字要求和频繁停顿；整体太慢优先恢复基础聊天语速；太甜优先撤掉幼态与气声；“嗯”错误优先改局部鼻音指令。先保持已认可的核心音色描述稳定，避免每次把全部 Prompt 重写成另一种声音。

对当前已授权的生成，初次失败复核后最多自动追加一次完整重生成。仍不达标就保留可用旧版、说明具体缺陷和建议，不反复付费尝试。用户另行明确要求继续时再执行。
