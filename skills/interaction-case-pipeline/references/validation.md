# 验收与增量恢复

校验结构、交互与音频三个层面。报告已做的检查，保留未完成项；模拟时序、生成后对齐时序和生产日志实测分开。

## 自动检查

在项目根目录使用当前仓库的 `npm run case:validate -- <源包目录>` 和 `npm run case:build -- <源包目录>`。阶段未生成音频时，不宣称完整包通过；先核对脚本及结构，待音频到齐执行完整校验。

核对：UUID 身份稳定；manifest 与数据 ID/标题一致；毫秒范围；固定七轨；工具定义与实际调用、参数、返回配对及依赖一致；引用源音频存在且切点有效；回应间隔；打断各边界顺序；真实语音重叠；Annotation 对应表达；audio.play/audio.stop 及助手间隔；总时长与最终音频一致。

## 语义与听感

- 每个决策使用当时可见的信息，工具返回重新核对最新意图。
- 在途修改不提前成功、不重复创建，不播报失效旧结果。
- 用户控制为站内实际动作；口头确认、跳转、支付成功分开。
- 连续用户句未被拆开，未播出部分不进入历史轮。
- 使用 voice.md 的片段抽听清单，核对同角色音色、聊天自然度、鼻音、英文词、尾音和环境声。
- ASR 与样本波形均不能替代听感验收。无法试听时提供音频供用户确认。

## 平台检查

导入后检查七轨顺序、空轨默认折叠、音频与波形、播放定位、工具块及 JSON 详情。下载 ZIP 后在隔离测试目录/浏览器导入，检查同 ID 更新、刷新保留及音频引用。用户和助手最终 WAV 的物理左右声道需要检查实际样本，不能仅凭 Meta 标记判断。

只运行与改动相关的验证。纯标题和样式不重生成音频；修改台词后重新对齐关联时间，修改工具后重查 JSON 和依赖，修改音频后更新合成缓存。

## 失败恢复

记录已确认内容、成功产物、失败环节与下一步到源包说明。认证/额度失败不重试；已成功生成的响应优先恢复；漏词或音色失败诊断后最多自动追加一次完整母带生成。仍失败保留原版并报告具体缺陷。已有生成授权不扩展为未来无限请求。

导入失败保持当前版本；ZIP 缺少源文件时说明缺失，不能补造母带或生成记录。源码与工具适配器确实不支持当前资产类型时，完成适配和验证或明确报告阻塞，不用删除功能换取校验通过。

表达控制逐条核对助手片段与 JSON 的起止时间、稳定引用；悄悄话无整段覆盖、无助手音频、无 Loading，移动或调整后的关联和导出保持一致。详见 [表达规则](expression.md)。

起点校验：仅用户语音允许任意整数毫秒；其他六轨的每个片段均须满足 `start_at_ms % 400 == 0`。同步检查关联 JSON，助手末端按实际音频时长保留。
