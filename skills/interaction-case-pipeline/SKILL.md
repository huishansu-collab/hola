# 交互 Case 全流程生成

用户给出场景描述后，完成可继续编辑、可追踪来源、可播放的 Case。只做用户当前授权的阶段；识别“先给大纲”“确认后生成”“只修改某一句”等范围。用户的新要求优先于默认音色和样例。默认完成路径为“开场信息 → 脚本故事线 → 确认生成 → 完整制作 → 可下载的 case.zip”。

## 开场信息收集

开始新 Case 时，先集中询问以下缺失信息，等待回答后确定角色音色：

1. “这个 Case 中用户角色的性别是男还是女？”允许用户给出其他具体声音要求。
2. “用户角色大约多大年龄？”可提供具体年龄或年龄段。
3. “TTS 默认使用 Seed Audio 1.0。请配置 API Key，或提供已配置的私有认证文件路径。”

这里询问 Case 中的用户角色，不推断实际操作者的性别或年龄。助手仍沿用已确认的 24～25 岁女性默认音色，除非用户另行指定。不要自行默认用户为男性或女性。

同一请求已经给出的信息直接采用，当前会话已经确认的配置继续复用，只追问缺失项。模型默认为 `seed-audio-1.0`，用户明确指定其他服务或模型时采用其选择。使用可用的提问界面一次收集性别和年龄；凭据使用安全配置入口或本地私有文件，不要求在普通聊天里粘贴明文 Key。

只要求大纲、台词或脚本时，可以先收集角色信息，凭据留到进入音频阶段。完整制作任务在开场确认凭据是否已配置；尚未配置时继续无关的场景与工具准备，TTS 必须等配置和生成授权具备后执行。提供 Key 本身不替代脚本确认和生成授权。

仅将角色性别、年龄和模型名称保存到 Case 制作说明。API Key 不进入 Prompt、Case JSON、Skill、日志、ZIP、TAR 或源码包。具体配置约定见 [TTS 与对齐](references/tts.md)。

## 入口与事实来源

1. 定位用户当前仓库或源包，读取项目数据契约、CLI 入口和已有制作状态。不依赖个人绝对路径，不读取凭据内容来确认配置。
2. 以当前项目 `docs/case-package-v1.md` 和共享校验器为格式依据；这里的 [数据契约](references/data.md) 描述当前兼容方式。
3. 新 Case 只生成一次 UUID v7。编辑、生成、构建、下载、导入沿用原 ID；明确复制成新 Case 才生成新 ID。内容指纹与 Case ID 分开。
4. 可复用已安装的 `full-duplex-case-builder` 与 `seed-dialogue-audio`。本包已包含必需规范与 TTS 执行入口，缺少个人 Skill 时依然可用。旧 Skill 中 plan、revision、playback 轨道或逐 Case 硬编码规则不覆盖当前七轨契约。

## 执行流程

### 1. 需求与任务

读 [交互展开](references/interaction.md)。明确目标、完成边界、角色、上下文和合理假设，规划子任务的输入、依赖、输出与成功条件。工具响应默认模拟，明确标记；写进脚本的订票、支付、叫车、发消息均不构成真实执行授权。

### 2. 优先交付脚本故事线，确认后生成

完成开场信息收集后，优先给用户可阅读、可修改的脚本故事线。凭据尚未配置不影响这一步；不要先输出大段 JSON、技术实现或开始 TTS。

脚本预览包含：

- Case 标题、一句话目标、必要假设及当前版本号。
- 用户与助手角色、年龄、音色和场景设定。
- 按发生顺序呈现的完整对白，穿插必要的工具等待、用户操作或世界信号。
- 打断点、慢说、鼻音、任务改口等实际需要的交互；只使用当时可见的信息。
- 简短结局及预计时长，设计时间标为预计，生成后按实际录音对齐。

预览末尾明确询问：“是否按这个版本开始生成完整 Case ZIP？确认后将生成语音、对齐时间线、校验数据，并提供 case.zip。也可以直接告诉我需要修改的地方。”有提问界面时提供“确认，开始生成”和“继续修改脚本”两个选项，不把默认选中当成用户回答。

用户确认当前脚本后，该确认覆盖本次完整制作：数据、TTS、对齐、校验、打包和下载交付，沿用此前提供的凭据。无需在每个内部步骤再次确认。关键台词、角色或目标必须新增变更时，先呈现变更；普通音频对齐与格式修复继续执行。

用户没有确认、选择继续修改，或只给出修正意见时，留在共创阶段：保留已认可部分，更新故事线版本，简短说明变化，再询问是否开始生成。沉默、提供 API Key、选择性别年龄都不算生成确认。此阶段可保存草稿，不调用付费 TTS，不用无音频的草稿包冒充完整 case.zip。用户已明确确认当前版本并要求生成时直接继续，不重复索要同一确认。

仅要求大纲、台词或 Prompt 时交付指定内容。后续再明确要求完整生成时进入此确认流程。

### 3. 源包与数据

按 [数据契约](references/data.md) 生成 manifest、说明、脚本、标准 JSON、timeline。模板位于 [assets/case-template.json](assets/case-template.json)，需要补齐内容和 ID 后使用。

表达控制按 [逐条表达标注规则](references/expression.md) 执行：对齐对应 Assistant 回复，悄悄话逐条标仅文字，编辑后同步关联 JSON。

所有 Case 保留用户、用户控制、助手、表达控制、世界、后台判断、工具调用七轨。无内容的轨道交由平台默认折叠。以标准数据为对白与工具事件的时间事实来源，不重复手写多套时间。

### 4. 声音制作

生成前必读 [声音描述与验收](references/voice.md)，再按 [TTS 与对齐](references/tts.md) 执行。

默认助手为 24～25 岁自然女声，按熟人聊天的语气说话。把稳定音色、局部表达与台词分开，使用精简的执行 Prompt；不把诊断清单整段塞给 TTS。按完整母带维持角色音色一致，再依照实际录音剪辑。

### 5. 对齐与校验

按音频实际时长回写时序和依赖；按 [验收与恢复](references/validation.md) 检查语音、语义、时间线、JSON 和工具关联。全局默认原速，不以变速弥补节奏错误。试听不合格时按问题类型调整 Prompt，在当前授权范围内有限重生成。

### 6. 构建与交付

读 [平台与打包](references/platform.md)。构建角色双声道音频、真实波形和完整数据，打包并核对完整 ZIP。默认交付文件名为 `case.zip`，保存到当前 Case 独立输出目录避免覆盖其他 Case，包内 manifest 保留 UUID v7 身份。

最终回复提供真实、可下载的 case.zip 链接，并简述内容与校验结果。不能仅给源目录、命令、JSON 或 TAR。平台导入/发布按用户明确范围执行；只要求 ZIP 时不强制修改网站。TAR 是可选的最终音频交付附件，不能代替完整 ZIP。

报告实际完成的产物、校验结果和仍需试听的问题。当前适配器支持本地构建及平台导入；团队发布、提交审核和资源池合入需要实际接口与权限，不编造命令或宣称已上线。

## 修改与恢复

- 从现有源包继续：找出已确认脚本、音频母带、切点、构建产物与上次失败环节。
- 改台词或音色：重生成受影响角色的完整对白母带，重新切点并检查后续时序；保留其他已验收角色。
- 改工具或参数：更新 Events、Meta tools、依赖、轨道及受影响对白。
- 改时间：更新关联标注、播放边界、时长、音频合成和缓存指纹。
- 纯界面调整：不触发付费生成。
- 保留上一版可用资源。认证、额度失败停止调用；下载或解析失败先恢复原结果，避免重复收费。
