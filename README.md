# Principle 工作台 · 从想法到可评审文档

一个面向产品团队的决策辅助工作台 Demo。把一号位的判断显性化，让小同学沿同一套路径产出：
**为什么做、为谁做、做到什么程度、哪些暂时不做、需要谁一起完成。**

按真实的**三阶段流程**推进，每阶段严格对齐真实**文档范本**：

| 阶段 | 回答的问题 | 氛围 | 退出条件 | GATE 评审人 |
|---|---|---|---|---|
| **冒烟** SMOKE | 值不值得做、大概多复杂 | chill 对齐 · 容忍推翻 | 各方对方向和复杂度量级、无重大分歧 | 需求提出方 · 执行负责人 · Kay |
| **Draft** STRUCTURE | 核心方案长什么样、关键需求加线框图 | 收敛 · 只聚焦关键需求 | 线框图和核心流程被 UED、研发确认可行 | 冒烟三方 + UED · 研发 · Kay |
| **PRD** DETAIL | 每个细节怎么落地 · 主视觉/文案/埋点/名词表 | 严肃 · 定稿即承诺 | 文档冻结，后续变更走 change log | UI: Kay / 细节：执行层自闭环 |

> 冒烟对齐方向 · Draft 对齐结构 · PRD 对齐细节，让否决发生在最便宜的时候（推翻成本随阶段递增）。
> 跳阶段：中型需求从 Draft 起步，小改动直接写 PRD（豁免须在需求登记注明）。

## 核心能力：上传 demo 物料 → 自动分析 → 产出结构化文档

在任一阶段右侧上传要走冒烟/Draft 的 demo 物料，平台自动把它映射进当前阶段的文档：

- **图片 / 截图** → 充当范本里「必填」的**线框图 / 高保真 / 竞品截图**
- **视频 / 录屏** → 充当 **demo 演示证据**
- **HTML / 网页** → **抽取正文关键信息**填入文档字段
- 缺的内容一律标「待补充」，不编造事实

## 文档范本（严格对齐）

- **冒烟**：一句话结论 → 背景 → 目标/非目标 → 思路&线框图（方案方向 + 尚未验证的假设）→ 复杂度预判（研发/设计/依赖方 大/中/小）→ 开放问题
- **Draft**：基本信息 → 一句话结论 → 需求背景与用户价值 → 竞品分析（**截图必填**）→ 关键功能（**线框图必填**）→ 不在本期
- **PRD**：主流程与状态 → 主视觉/视觉稿 → 文案表 → 埋点表 → 名词表 → Change Log（冻结即承诺）

每份文档右侧实时显示**完成度**（对照该阶段范本必填项）与**缺失项提示**，并可一键导出结构化 Markdown、在 GATE 处记录评审结论。

## 运行

纯静态、零依赖、零构建：

```bash
open index.html            # macOS
xdg-open index.html        # Linux
# 或本地起静态服务（推荐）
python3 -m http.server 8080   # 访问 http://localhost:8080
```

数据（含上传物料）保存在浏览器 `localStorage`。侧栏「载入示例」载入标杆（Step AI IDE 冒烟→Draft），「清空数据」重置。

## 页面

| 页面 | 作用 |
|---|---|
| 工作台 | 需求列表、三阶段进度、负责人、物料数、评审结论，按阶段筛选 |
| 新建需求 | 输入想法 + 上传物料，选择方向与起始阶段 |
| 冒烟 / Draft / PRD | 章节化文档编辑 + 上传自动分析 + 完成度/缺失项 + GATE 评审 + 导出 |
| 三阶段流程 | 三阶段卡片 + Kay 递减介入曲线 + 推翻成本 |
| 技能库 | 把范式/范本/规范沉淀成可复用 Skill（见下） |
| 团队手册 | **大部门规定**（Intelligence Works Team Handbook：文档与写作/会议/沟通/产品，含 Bad/Good case，只读）+ **我的团队工作范式**（参考规定就地编辑、可导出） |
| 总原则 | 判断原则 + 三份文档范本目录 |

## 技能库（Skills）

把散在各处的模板与规则沉淀成模块化、可复用的 Skill——任何内容进来都沿同一套 skill 组合产出。
组合管道：**内容进来 → 框架定结构 → 做图归位物料 → 内容校对文字 → 设计统一呈现 → 评审出结论**。

| Skill | 类别 | 能力 | 沉淀自 |
|---|---|---|---|
| 框架 Skill | 框架 | 套冒烟/Draft/PRD 骨架、完成度与缺失项、GATE | 三份文档范本 |
| 做图 Skill | 做图 | 上传物料→线框图/截图归位、HTML 抽正文 | 上传自动分析 |
| 内容 Skill | 内容 | **写作体检（可运行校对）**：中英空格/慎用加重/数字用 K/结论优先 | 大部门《文档与写作》 |
| 设计 Skill | 设计 | 苹方 + 4 级字号、语义色、卡片/表格/间距 | 视觉规范 |
| 评审 Skill | 评审 | 缺失项汇总、结论建议、评审记录导出 | GATE 评审门槛 |

`skills.js` 里每个 skill 既是知识载荷也带可运行行为（如 `lintText()`）；文档页右侧「写作体检」按钮即调用内容 Skill 对当前正文即时校对。

## 视觉规范

- 字体：Apple **苹方**（PingFang SC）优先，带完整回退栈。
- 字号：全站**只用 4 种**（`--fs-1..4` = 20 / 15 / 13.5 / 12），层级靠字重与颜色，不靠字号堆叠——贴手册的克制黑白感。

## 方向切换的 SOP

选择方向（通用 / 语音双工 / 通话助攻 / Memory / Agentic）会调整假设、复杂度与开放问题的建议。

## 代码结构

```
index.html      页面骨架与侧栏
styles.css       全部样式（苹方 + 4 级字号，响应式）
data.js          三阶段配置 + 方向 + 总原则 + 三份文档范本 + 团队手册 + 工作范式
generator.js     Demo 版「一号位助手」：冒烟/Draft/PRD 生成 · 上传自动分析 · 缺失项 · Markdown 导出
skills.js        Skill 注册表（框架/做图/内容/设计/评审）+ 内容 Skill 的可运行校对 lintText()
app.js           SPA 路由、localStorage 状态、各页面渲染与交互
```

## 关于「自动分析」

本 Demo 可**离线运行**：`generator.js` 用规则 + 模板做分析——HTML 客户端抽正文、图片/视频挂载为必填视觉、文本映射到字段，缺内容标「待补充」，不编造竞品事实。
接入真实模型时，只需把 `generateSmoke` / `generateDraft` / `generatePRD` / `analyzeUpload` 替换为对应阶段的 Prompt 调用，页面与数据结构无需改动。

> 演示用途，不含后端与真实模型调用。
