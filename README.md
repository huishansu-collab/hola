# Principle 工作台 · 从想法到可评审 Draft

一个面向产品团队的「从想法到可评审 Draft」决策辅助工作台的 Demo。
把一号位的判断原则显性化，让小同学沿着同一套路径产出：**为什么做、为谁做、做到什么程度、哪些暂时不做、需要谁一起完成**。

三类核心产物：

- **Principle** —— 判断一件事是否值得做、先做什么、什么算完成。
- **SOP** —— 按方向和阶段给出下一步动作、必填问题和评审门槛。
- **Draft** —— 把结论沉淀成可评审、可协作、可追踪的需求草案。

## 运行

纯静态、零依赖、零构建。任选其一：

```bash
# 方式一：直接用浏览器打开
open index.html            # macOS
xdg-open index.html        # Linux

# 方式二：本地起个静态服务（推荐，避免个别浏览器的 file:// 限制）
python3 -m http.server 8080
# 然后访问 http://localhost:8080
```

数据保存在浏览器 `localStorage`，刷新不丢失。侧栏「清空数据」可重置。

## 首版范围（对应文档 §8）

- 需求输入（想法 / 会议记录）
- 方向 / 阶段选择
- 冒烟卡片生成
- Draft 生成
- 缺失项提示（对照「进入排期的完成标准」）
- 评审结论导出（Markdown，可复制 / 下载）

架构图在线编辑、复杂权限、历史版本对比、自动接入研发系统留待后续版本。

## 页面结构（对应文档 §6）

| 页面 | 作用 |
|---|---|
| 工作台 | 需求列表、阶段、负责人、最近结论，按阶段筛选 |
| 新建需求 | 输入想法，选择方向与起始阶段 |
| 冒烟讨论 | 左侧对话，右侧实时生成价值主张、假设与 P0 主路径 |
| Draft | 章节化编辑，右侧显示缺失项、完成度、风险与指标 |
| 架构拆解 | 四个模块卡片，按方向高亮当前模块并保留架构占位 |
| 评审 / 排期 | 通过 / 补充 / 暂缓 / 推翻，生成并导出评审记录 |
| 总原则 | 判断原则、完成标准与全流程总览 |

## 按方向切换的 SOP（对应文档 §5）

选择方向会替换必填问题、风险清单、指标建议与架构占位：

- **通用** —— 先价值后方案的标准路径。
- **语音双工** —— 自然打断、响应时延、轮次衔接、噪声环境。
- **通话助攻** —— 实时信息是否在正确时机出现、建议是否被采纳。
- **Memory** —— 记忆是否有用 / 准确 / 可控，支持查看 / 修改 / 删除。
- **Agentic** —— 任务成功率、工具选择、失败恢复、人工接管。

## 代码结构

```
index.html      页面骨架与侧栏
styles.css       全部样式（浅色主题，响应式）
data.js          静态配置：方向、阶段、总原则、完成标准
generator.js     Demo 版「一号位助手」：冒烟卡片 / Draft 骨架 / 缺失项检测 / Markdown 导出
app.js           SPA 路由、localStorage 状态、各页面渲染与交互
```

## 关于「助手」生成

本 Demo 可**离线运行**：`generator.js` 用规则 + 模板把输入结构化，并区分
「已知事实 / 用户假设 / 待验证问题」——信息不足处一律标记为「待补充」，
**不编造竞品事实**，与文档 §7 的系统 Prompt 约束一致。

接入真实模型时，只需把 `generateSmokeCard` / `generateDraft` / `suggestReview`
替换为文档 §7 对应阶段 Prompt 的调用即可，页面与数据结构无需改动。

> 本项目为演示用途，不含后端与真实模型调用。
